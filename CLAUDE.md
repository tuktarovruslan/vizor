# Правила проекта

Нарушать нельзя.

1. Коммитить только с явного разрешения владельца; разрешение действует на один коммит.
2. Коммиты идут в `develop`. В `master` только по явной команде владельца.

# Vizor и манифест vizor.json

`vizor` — сервис наблюдения за всеми проектами warehouse (http://localhost:4000). Запуск всего: `node dev.mjs` из корня warehouse.

Каждый проект обязан иметь `vizor.json` в своём корне, иначе Vizor и `dev.mjs` его не увидят:

- `name` — имя проекта;
- `services[]` — `id`, `type` (backend/frontend/…), `stack`, `dir` (папка сервиса внутри проекта), `command` (запуск), `url`, `health` (путь проверки, ответ 2xx; если JSON с `status`, то `ok`);
- `links[]` — связи между сервисами: `from`, `to`, `label`, `via` (путь, запрашиваемый у `from.url`; проверяет всю цепочку).

Для БД и прочих не-HTTP сервисов: `url` вида `tcp://host:port` без `health` — Vizor проверяет только открытость порта. Живость связи сервис → БД задаётся полем `field` у link: связь зелёная, если в JSON-ответе `via` это поле равно `ok` (например `db` в `/api/health`).

Новый проект или сервис: добавь запись в `vizor.json`, перезапуск Vizor не нужен. Пример: `plus/vizor.json`.

# Graphify

Граф знаний проектов строит скилл `graphify` (CLI в `~/.venvs/graphify/Scripts/graphify`). Выходные файлы лежат в `<проект>/graphify-out/` и в git не попадают.

- Вопросы об устройстве проекта (архитектура, кто кого вызывает, где что лежит) сначала решай по `graphify-out/GRAPH_REPORT.md` и `graph.json` (`graphify explain`, `graphify path`), и только потом читай файлы.
- Нет `graphify-out/` у проекта — построй: `graphify update .` из корня проекта (без LLM, без затрат).
- Перестраивать граф (`graphify update .`) можно только после коммитов — не после правок кода в рабочей папке. Пока изменения не закоммичены, граф считается устаревшим: свежее состояние смотри по исходникам.
- Граф не видит Vue-файлы, `server.js` и SCSS — по ним читай исходники.
